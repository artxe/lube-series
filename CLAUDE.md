# lube-series
- `eslint.config.js` and the root `tsconfig.json` are the canonical lint and tsc config; package `tsconfig.json` files only extend the root.
- Types (owner's rule): never `any` (JSDoc `*`) or `object`. `unknown` only where a value is really arbitrary, such as input checked at runtime, or as the bridge a double cast needs. A variable is typed by a `/** @type {T} */` tag on its declaration, never by casting its initializer, and a value flowing into a typed parameter or return (an `any` from `JSON.parse` too) needs no cast; a cast is only for what a tag cannot type, such as narrowing `T | null` to `T`. No `@typedef` or `@callback` in `.js`.
- `pnpm dts` appends `export * from "../public.js"` to the generated declaration of every entry, so users import values and types from the package itself, e.g. `import { flow, type Flow } from "async-lube"`; a name declared in both files would be ambiguous, so a type only the generated `types/` needs, such as the shape of an exported error class, stays in `public.d.ts` without `export` and under another name (`HttpErrorLike`).
- Each `exports` entry is `{ "types": "./types/….d.ts", "default": "./src/….js" }`; CommonJS callers `require` the packages through Node.js `require(esm)`. `pnpm dts` (`scripts/tsc_with_clean.js`) writes `types/`, rebuilt by `prepack`.
- Default exports are anonymous (owner's choice) unless the module calls them by name, as `http` does: `export default function(...) {}`, or `export default /** @type {T} */(value)/**/` for a value. `types/` is written by tsc 7, which keeps a doc comment before `export default <expression>`; tsc 6 drops it, and both drop description text inside the cast comment itself. tsc 7.0.2 drops `@overload` JSDoc and crashes on `@overload` before an anonymous function, so an overloaded export casts its function to a callable type from `public.d.ts` whose signatures carry the docs, as `channel` does; the function stays a declaration, which `func-style` asks for, unless it is the default export.
- Changes go in `packages/<name>/CHANGELOG.md` under `## Unreleased`, or in the top version section while that version is not on npm yet (`npm view <name> version`).
- Finish a change with the `verify` skill; measure hot paths with the `benchmark` skill.
