# lube-series
- `eslint.config.js` and the root `tsconfig.json` are the canonical lint and tsc config shared with the sibling repos (aim-dojo, click-css, dom-eater); package `tsconfig.json` files only extend the root.
- `tsc` is TypeScript 7 and must pass. The `typescript` dependency stays 6 because typescript-eslint needs that API, not to check with it.
- Types (owner's rule): never `any` (JSDoc `*`) or `object`. `unknown` only where a value is really arbitrary, such as input checked at runtime, or as the bridge a double cast needs. No `@typedef` or `@callback` in `.js`.
- `public.d.ts` holds the types a package's users name and imports nothing from `src` or `private.d.ts`. `pnpm dts` appends `export * from "../public.js"` to the generated declaration of every entry, so users import values and types from the package itself, e.g. `import { flow, type Flow } from "async-lube"`; a name declared in both files would be ambiguous, so a type only the generated `types/` needs, such as the shape of an exported error class, stays in `public.d.ts` without `export` and under another name (`HttpErrorLike`). `private.d.ts` holds the types used only inside the package and is not published, so `files` lists the declarations the entries reach instead of all of `types/`.
- Packages are ES modules only: each `exports` entry is `{ "types": "./types/….d.ts", "default": "./src/….js" }`, `types` first, with no CommonJS build; CommonJS callers `require` them through Node.js `require(esm)`. `pnpm dts` (`scripts/tsc_with_clean.js`) writes `types/`, the only build output, gitignored, never edited and rebuilt by `prepack`.
- Default exports are anonymous (owner's choice) unless the module calls them by name, as `http` does: `export default function(...) {}`, or `export default /** @type {T} */(value)/**/` for a value. `types/` is written by tsc 7, which keeps a doc comment before `export default <expression>`; tsc 6 drops it, and both drop description text inside the cast comment itself. tsc 7.0.2 drops `@overload` JSDoc and crashes on `@overload` before an anonymous function, so an overloaded export casts its function to a callable type from `public.d.ts` whose signatures carry the docs, as `channel` does; the function stays a declaration, which `func-style` asks for, unless it is the default export.
- Comments: only JSDoc type tags, casts and `// eslint-` or `// @ts-` directives, no prose, in src, tests, scripts and configs. Exception: exported functions whose JSDoc becomes `types/*.d.ts`, and handwritten `public.d.ts`, keep user-facing docs (what it does, how to call it, `@example`), never implementation notes.
- Record user-facing changes in `packages/<name>/CHANGELOG.md` under `## Unreleased`, or in the top version section while that version is not on npm yet (`npm view <name> version`); entries describe the resulting behavior, not the history.
- Finish a change with the `verify` skill; measure hot paths with the `benchmark` skill.
- The sibling repository `../dom-eater` is maintained with this one: after changing `eslint-plugin-lube`, `eslint.config.js` or the root `tsconfig.json`, update and verify it too (it consumes the plugin and keeps its own stricter rules).
