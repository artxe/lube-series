# TODO

What is left lives in two files at the repository root, one plain list item each (`- ...`, no checkbox):
- `TODO.md`: Claude's tasks, in the order they can be done, each naming what it waits for (a task, a decision, a check). Work wanted someday, a known gap of a finished part included, is a task too, at the end.
- No file holds the owner's decisions: one only the owner can make is asked in the session as soon as it comes up (in Korean: the question, the options, the recommendation first), at the latest in the session's final report, while the rest of `TODO.md` goes on; until answered its task stays in `TODO.md`, its item holding the question and the recommendation. Any other choice Claude makes itself, the best for the project's goal, and records where the work lands.
- `TODO.checks.md`: work Claude finished that only a person can confirm (another platform or PC, a real account, a design's look, the feel in play), each item as exact steps a person follows without writing code: the commands to paste, the URL to open, what to press, where to look, and the expected result as numbers or a concrete picture (what a readout shows, what appears where, what counts as a failure), never an open question ("does it look natural?"); where no ready page or test reaches the case, the task that adds the item builds one in the same commit. A look Claude can judge itself, headless and muted (screenshots, numbers a script prints), is checked by the part that builds it and never listed.

A request with several tasks goes into `TODO.md` first, before the work starts. Each item is deleted as soon as it is done, in the same commit as the work, so the files only ever list what is left (an emptied section or file goes too). A task found on the way that the request needs becomes an item too. The owner may write notes at the top of `TODO.md` in any language: a session takes them first, turning each into items or answering it, and deletes it.

A session may stop at any moment (a token or usage limit) and its transcript is deleted later, so nothing left open lives only in the session or its final report: whatever a task leaves open goes into one of these files in the task's commit (a follow-up offered, a flaw or an unchecked case found on the way). A task bigger than one part is committed part by part, each commit rewriting its item to say what is done, what comes next and where unmerged work is (a branch, a worktree), so a cut-off session loses at most the part in hand. Each item stands on its own for a session that never saw this one: what, the numbers, and where the known facts are (the file path and symbol, not a line number, which moves, nor a commit: no Markdown file names one, since the history is folded and looking one up wastes a turn; the cause if it was found, or that it was not traced; the command that measures it). A request that does not say what it is about answers one of these items, so read `TODO.md` first. These files are searched by Grep `-o` with a short pattern, `count` or `files_with_matches`, and a `head_limit`: a plain Grep or `git grep` prints whole items, a long line each.

`TODO.md` is always ready for a new session told only to proceed with it: such a session first takes every open decision its items hold (found by Grep), before any task: one Claude can settle (the usual case) it decides itself, the best for the project's goal, and records in its item; only one that needs the owner (money, an account, what is published, a taste the owner reserved) it asks; then it starts every task whose wait is met at once, one subagent in its own worktree each (`models.md`), save tasks that touch the same files, which go one after another, and asks the owner the decisions its next task needs. An answer goes into its task's item in the same commit, and a failed check becomes a task.

A public repository keeps none of these files once a task ends: the task does its follow-ups itself, asks the owner the decisions its work needs in the session, before the work that waits on them, and names its checks and any gap it leaves in its final report. Only a task cut off midway leaves them there, and the next session takes them first.
