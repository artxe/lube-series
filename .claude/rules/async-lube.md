- Intent (owner): complex async as simple procedural code without performance loss. flow keeps the dag style (plain functions as nodes, dependencies passed by reference and received as arguments, topological order) and must scale to AI agents and large batches; http is frontend-first.
- Never add abort listeners per item on a shared AbortSignal; go through `on_abort` in `src/signal.js`, because EventTarget add and remove are linear.
- Do not build Error objects on reset or other hot paths unless something is aborted with them; stack capture is slow.
- `src/flow/` splits a run by concern: `run.js` builds the per-run context `c` (`RunContext`) and the run object, and every other module is plain functions that take `c` first, so a run allocates no closures. The modules import each other in cycles, which is fine while their top levels only declare. Change `record.status` only through `set_status` in `nodes.js`: it keeps the active count that lets `check_complete` return at once while a node is active. A flow definition's `list` is shared between a flow and the flows built from it and appended in place only when `list.length == count`.
- `each` and `input` are `flow.each` and `flow.input`, not package exports (owner's decision), since those names collide in user code. The static properties keep `src/flow/` in esbuild bundles of apps that import only `http` unless package.json declares `"sideEffects": false`, so keep that field and keep module top levels free of side effects.
- `run.status` reads the `sub_running` and `sub_waiting` counters that the `ON_CHANGE` of each sub-run keeps, and `send`, `reload` and `retry` report a changed status at once. Never scan `sub_runs` for a status or copy a backlog per dequeue.
- `context.sleep` of a flow node returns the promise of `sleep_until` itself for delays a timer can hold; one more `async` layer lets a reset node's cleanup run after its restart. Request options must not reuse a `RequestInit` key, e.g. `cache`, and `offload` worker code must not call `require`, since an eval worker inherits `--input-type=module`.
- A run is thenable, so an async API that hands one out resolves with `{ run }`; resolving with the run itself resolves with its result. Node keys are derived from the run ID and the start count of the node, never random per call: a snapshot saved before a key was read must reproduce it after a crash.
- `async-lube/durable` (`src/durable/index.js`) is the one subpath: it shares src modules with the main entry, and both import the same `src/errors.js`, so `instanceof CancelError` holds across them. `src/durable/` splits a worker by concern as `src/flow/` splits a run: `index.js` builds the worker `d` (`DurableWorker`) and the object it returns, and every other module is plain functions that take `d` first, and the execution second where they need one. `stop()` is final: a worker that stopped must never claim again, since a lease it owned still names it. `send` never unclaims a run whose lease another worker holds: it appends to `inbox`, which only the holder (on a write conflict, counting `absorbed`) or a claim moves into `events`. Done journal entries and events are never mutated, since `snapshot` and the `encode` cache share them between writes; the function only ever sees `copy()`s.
- `return()` of a stream must stop its source at once while a `next()` is pending, also through nested operators, and a pending `next()` of a source that fails after the loop left is caught. So the operators in `src/stream.js` are hand-written iterators, never async generators, and the async generators of `sse()` and the `ndjson` and event bodies reach users only through `watch_records` in `src/http/request.js`.
- Tests never race real time: files without real I/O (`flow`, `flow_recovery`, `flow_fuzz`, `stream`, `limiter`) run each test on fake timers in `nextTimerAsync` mode, durable and timeout tests advance fake timers by hand (a fake `fetch` stands in for the server when only the response matters), and tests against a real server or worker wait for a condition (`eventually`, `until`, `closes`, an `Atomics` gate) instead of a fixed sleep. `stream_fuzz` runs on the clock of `sim/clock.js`; `http_fuzz` and `socket_fuzz` use local servers with generous timeouts. Wall-clock bounds stay only for performance, and subprocess or CPU-heavy tests set their own timeout. Every seed of a simulation goes through `within` of `sim/seeds.js`, whose budget runs on the `setTimeout` captured before the fake clock is installed: a hang stops the simulated clock, so a watchdog that reads the installed `Date` or `setTimeout` never fires.
