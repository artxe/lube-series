- Intent (owner): feels like native syntax sugar with top performance, handles circular references everywhere and shares untouched values with the input instead of copying them.
- Built-in kinds are detected in `src/kind.js` through the prototype chain; only a value whose chain reaches no known prototype (another realm) falls back to `Object.prototype.toString`, and `resolve` brand-checks every kind, so a fake `Symbol.toStringTag` or a slotless object such as `Object.create(Date.prototype)` counts as a plain object instead of throwing.
- Benchmark-tuned, measure before restructuring: deepCopy copies an array with `slice()` and reads the items from the source array, not the copy; deepEqual's cycle memo and deepFreeze's visited set stay off until a depth or visit limit is passed, and deepMerge tracks no cycles until it restarts past the same limits; deepUpdate reaches a draft's state through a symbol answered by the proxy get trap, not a WeakMap, finalizes only the keys it recorded as touched, copies objects with a spread, not a key loop, and drafts Set members on the first iteration, not when the Set is copied; deepDiff keeps the pairs on its path in a flat trail and compares keys in order before falling back to `propertyIsEnumerable`.
- deepCopy copies the own keys of built-ins after cloning them, but never of String objects or typed arrays, whose index keys `Object.keys` would list. A view that covers a resizable buffer to its end is copied as length-tracking because that flag is not observable.
- Every function stays stack-safe at any depth: past a depth limit it creates the result's shell and queues the work that fills it, drained at the top level. deepEqual matches by hash first inside an `attempt`, caches results inside attempts only when no assumed pair was used, and restarts as an iterative bisimulation (`bisimilar`) when a tentative match would pass the depth limit or tentative comparisons exceed their budget. deepDiff restarts as a graph of pairs expanded once past the depth limit, on the first cycle, or when a pair that produced changes is reached again after a visit limit; it lists a change under every path when the changed pairs are acyclic and once per pair when they are not. Long arrays go through `sparse_indices` in `src/kind.js` so a sparse array costs its items, not its length.
- deepEqual and deepDiff match Map and Set members only among the candidates of `hash_candidates` in `src/hash.js` (buckets over 8 members are split again by `strong_hash`), so the hash must stay consistent with deepEqual: equal values always hash alike, and a collision costs time, never correctness.
- `test/data-lube/properties.test.js` holds seeded property checks: the same random mutations run on a draft and on a `deepCopy`, and diffs must round trip. `test/data-lube/oracle.test.js` checks every function against reference implementations (deepUpdate against a reference clone: structure, sharing, copy-vs-share, freezing, untouched input); run it with `DATA_LUBE_SEEDS=5000` (cases per config, about a minute) and another `DATA_LUBE_SEED` when changing these functions, and `DATA_LUBE_CASE=<seed>` reruns one failing case.
- deepUpdate deep-freezes objects added under a frozen parent in place, even ones other code holds (owner's decision, as immer's auto freeze does): copying them breaks sharing, and leaving them unfrozen breaks the frozen state. It never freezes objects of the input: `finalize_value` queues no draft for freezing, and the freeze walk stops at `scope.kept`, which `keep` fills with results of drafts found inside new values and with the non-drafted objects, `Map` keys and `Set` members the traps hand out from a base. Objects from a `deepPatch` change list (`src/deep_patch.js`, which drafts through `update`) are the exception: `copy_of` copies them (one `copy_data` of all keys and values, so they stay shared with each other) before they go under a frozen parent or replace a frozen root, since they belong to the diffed `after`; `copy_data` keeps objects whose prototype is not a built-in one (class instances, subclasses of built-ins) by reference, so they are frozen in place instead of losing private fields.
- While a recipe runs (`drafts.active` in `src/draft.js`), deepCopy, deepEqual and deepDiff first `snapshot` their arguments (one node per raw object, whether reached through a draft or not), while deepMerge merges drafts through their traps so untouched parts stay drafts: a quick scan skips arguments without drafts, and with a single active recipe a value equal to its draft's base value is trusted to hold no drafts, except in graph mode, where a base value can still reach changed objects. Outside recipes they pay only the counter check.
- deepUpdate (owner's decision) assumes an unseen value is a tree: no walk. Graph mode (`scope.graph`: one draft per original in `scope.drafts`, and `link` walking the whole current graph to draft and touch every container that reaches a changed one; snapshots walk everything too) runs with `{ graph: true }`, for a value `shapes` in `src/deep_update.js` records as a graph, or after a second draft request for an original found in `scope.listed`: searched linearly for the first drafts, then through `scope.bases`, a Set of their originals that `listed_again` grows with one `add` per draft and reads by its size (benchmark-tuned, not a Map). Every tree-mode draft must reach `scope.bases` once it exists, as the Set `add` trap does. Results are recorded from `link`, or as graphs when tree mode sees sharing added by the recipe (`away`/`placed` in the traps and finalize); results of an assumed tree stay unknown. The one-entry `recent` cache holds the last input and result strongly on purpose, not in a WeakMap, and always flushes graphs. Detection must not change tree semantics: a restored or re-added original forgets its listed draft. deepPatch change lists always apply by path, without identity. Sharing is followed through enumerable string keys, array indexes, Map entries and Set members of drafted kinds only; class instance fields keep the original (documented).
