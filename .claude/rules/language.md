# Language

The owner reads only Korean. Every message to the owner is in Korean, whatever language the prompt, files, tool output or subagent reports are in: the short briefings between tool calls as much as the final report. Each says in plain words what a thing is and what it changes for the owner before any options: no internal label (a part number, a commit hash, a skill or task name) and no jargon left unexplained. The owner cannot tell from the editor whether a session is still at work (its busy mark goes off while a background command or a wait still runs), so the last message of every turn ends with one bold status line saying it, so the owner never has to ask: done, the session may be closed (and whether an app or server Claude or the owner opened for it may close too); still running in the background (what), so the session must stay open, though nothing shows it, and Claude goes on by itself when it ends; waiting for the owner (the question); or to go on in a new session (the line to start it with).

What Claude reads is in English: `CLAUDE.md`, `.claude/` (rules, skills, `api/`), `TODO.md`, design notes kept for Claude's work (a `design/` folder), subagent briefs and their reports. Every other Markdown file is for the owner and is in Korean: README, docs, `TODO.checks.md`. A public repository, read by outsiders, has every Markdown file in English. No project's own file sets another language for them, and no third language is written for any reader. One appears only to quote what the code, the UI or the players use, or in a guide to the text a game ships in that language (its dialogue style).

In Markdown, replies included, a range is never written with `~` (two on one line strike out the text between them): use an en dash (`2–3`).
