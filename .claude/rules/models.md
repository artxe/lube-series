# Models

The main session (Opus or Fable) keeps the judgment: what to change, the project's rules, the edits that need them, and what proves the work done. Work it can hand off goes to a subagent (the Agent tool's `model`) on the cheapest model that does it well, even when the main session only waits for it: a turn of the main session costs more than a cheap subagent's whole run, the more so in a long session. Running builds, tests, checks and scripts and reporting their output, commits from a given list, and cleanups go down; the main session reads the report and judges it. It checks what comes back before using it:
- `haiku`: mechanical work with exact instructions: finding files or strings, running a script or a test command and reporting its output, bulk edits from a given list, renames; and any part whose result a command checks (its tests pass, the build succeeds, a count matches), even when it takes a few tries. After two failed tries the part goes to `sonnet`.
- `sonnet`: read-only investigation of one area, and scoped changes or tests whose cause and fix are already decided: a feature whose brief fixes its files, API and tests is sonnet however long or central it is.
- `opus`: root-cause hunts across several files or systems, and design work.
- `fable`: only what is hard and costly to get wrong: a bug that resisted Opus, an architecture decision, a subtle timing, concurrency or replay issue.

A main session on Fable still hands haiku, sonnet and opus work down; one on Opus hands fable-level work to a `fable` subagent. A lookup the main session can do in one or two tool calls stays in the main session.

Tokens run out before time does. Every turn re-reads the whole context, so a session's cost grows with its length times its size, and those re-reads are most of it; a cache read costs the same on Sonnet as on Opus (Haiku's is a twentieth), so a small context saves more than a cheaper model. A subagent takes one part it can finish in 50–100 tool calls; the main session cuts bigger work into such parts and hands them out one after another (or in worktrees), each brief naming the files and symbols its part needs so the agent explores nothing else. Sessions and subagents compact at 200K tokens (`CLAUDE_CODE_AUTO_COMPACT_WINDOW` in `.claude/settings.json`): a part that would need more is two parts. Each brief says so to the subagent: at about 100 tool calls it commits what works and stops, its report saying what is done and what comes next, which the main session hands out as the next part. The Agent tool's result gives the tokens a subagent used; one that ran past 200K, or explored what its brief should have named, makes the next brief smaller and more exact. Every session reads only the lines it needs (Grep first, then `offset` and `limit`), never re-reads an unchanged file, keeps command output short (a quiet or dot reporter; a long log written to a file and searched), and leaves long logs and big files to a subagent that reports only its conclusion.

The main session's own context grows with every request it takes, however small its subagents' parts. Once it passes about 100K tokens (several finished tasks, or a few dozen tool calls reading files), it starts no new part: it commits what works, leaves what comes next in `TODO.md` (`todo.md`), and ends its report by telling the owner to continue in a new session, with the line to start it with (that it proceed with `TODO.md`). A new request to such a session that does not need its context gets that advice before any work, and goes ahead in it only when the owner asks.

Every Agent call names its `model`: one without runs on the main session's. The main session edits itself only a change of a line or two, or one still being decided with the owner; a settled change of more is a part for a subagent, and a run of the owner's tweaks is cut into such parts before any edit.

Subagents run in the foreground (`run_in_background: false`), independent ones in parallel as several Agent calls in one message: the main session never ends its turn while one is working, since one left running when the turn ends looks stopped to the owner. A subagent's brief says the same for its own commands (`shell.md`).

A brief carries what the subagent cannot see: the decided design with file and line evidence, what it must not touch, and the rhythm of `verify.md`: its own tests while working, and at the end the linter and type check on its changed files with the tests of the area it touched. The full check is the main session's, once after the last part is merged. A subagent on a decided part (a `sonnet` or `haiku` one, or an `opus` one doing work whose design the brief fixes) runs at the Agent tool's `effort: "medium"`; a hunt or a design keeps the default.

Two subagents never build or test in the same working tree at once: independent work on one repository runs in parallel only in separate worktrees (`isolation: "worktree"`), otherwise one after another. A worktree starts from the local `HEAD`'s last commit (`worktree.baseRef` is `head` in `.claude/settings.json`), without uncommitted work or `node_modules`: Node finds the main tree's up the folders, so a Node project's tools run there by `npx` and `node`, never `pnpm`, which installs first. Its brief has the agent check with `git log -n 1` that it holds that commit, and commit on its branch; the main session merges the branches, runs the full check once and removes the worktrees. A follow-up to a finished subagent is a new foreground Agent call carrying the context it needs; SendMessage resumes it in the background, where the main session cannot wait for it.
