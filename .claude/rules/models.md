# Models

The main session (Opus or Fable) keeps the judgment: what to change, the project's rules, the edits that need them, and what proves the work done. Work it can hand off goes to a subagent (the Agent tool's `model`) on the cheapest model that does it well, even when the main session only waits for it: a turn of the main session costs more than a cheap subagent's whole run, the more so in a long session. Running builds, tests, checks and scripts and reporting their output, commits from a given list, and cleanups go down; the main session reads the report and judges it. It checks what comes back before using it:
- `haiku`: mechanical work with exact instructions: finding files or strings, running a script or a test command and reporting its output, bulk edits from a given list, renames; and any part whose result a command checks (its tests pass, the build succeeds, a count matches), even when it takes a few tries. After two failed tries the part goes to `sonnet`.
- `sonnet`: read-only investigation of one area, and scoped changes or tests whose cause and fix are already decided: a feature whose brief fixes its files, API and tests is sonnet however long or central it is.
- `opus`: root-cause hunts across several files or systems, and design work. A brief naming `opus` says in its first line which cause it hunts or what it designs; a hunt's brief asks for the cause, proven by a measurement or a failing test, never for a fix to try (`verify.md`); a brief that already fixes them is `sonnet`, and a brief naming `opus` never also asks it to build or fix. An opus part ends once the cause or design is found and proven (a failing test that pins it, a spike): it commits that, writes the fix or design down (files, API, tests left) and stops; building the rest is the next part, on `sonnet`. A hunt that has not found its cause by about 60 tool calls stops too, writing into the task's `TODO.md` item what it ruled out and how, so the next hunt starts there, never again from scratch.
- `fable`: only when the owner names it for a task (owner: it solves problems no better than Opus at twice the price). A bug or design that resisted Opus goes to a fresh `opus` part starting from what the last one ruled out.

A main session on Fable still hands haiku, sonnet and opus work down. A lookup the main session can do in one or two tool calls stays in the main session.

Tokens run out before time does. Every turn re-reads the whole context, so a session's cost grows with its length times its size, and those re-reads are most of it; a cache read costs the same on Sonnet as on Opus (Haiku's is a twentieth), so a small context saves more than a cheaper model. A subagent takes one part it can finish in 50–100 tool calls; the main session cuts bigger work into such parts and hands out at once every part that waits on no other, each in its own worktree, each brief naming the files and symbols its part needs so the agent explores nothing else. Sessions and subagents compact at 200K tokens (`CLAUDE_CODE_AUTO_COMPACT_WINDOW` in `.claude/settings.json`): a part that would need more is two parts. Each brief says so to the subagent: at about 100 tool calls, or once its context passes about 120K, it commits what works and stops, its report saying what is done and what comes next, which the main session hands out as the next part. The Agent tool's result gives the tokens a subagent used; one that ran past 200K, or explored what its brief should have named, makes the next brief smaller and more exact. A subagent that flounders (try after try, no progress) shows a defective brief, not a weak model: the next brief carries the evidence, the files and what is ruled out, on the same model. Every session reads only the lines it needs (Grep first, then `offset` and `limit`), never re-reads an unchanged file, keeps command output short (a quiet or dot reporter; a long log written to a file and searched), and leaves long logs and big files to a subagent that reports only its conclusion.

The main session's own context grows with every request it takes, however small its subagents' parts. Once it passes about 100K tokens (several finished tasks, or a few dozen tool calls reading files), it starts no new part: it commits what works, leaves what comes next in `TODO.md` (`todo.md`), and ends its report by telling the owner to continue in a new session, with the line to start it with (that it proceed with `TODO.md`). A new request to such a session that does not need its context gets that advice before any work, and goes ahead in it only when the owner asks.

Every Agent call names its `model`: one without runs on the main session's. The main session edits itself only a change of a line or two, or one still being decided with the owner; a settled change of more is a part for a subagent, and a run of the owner's tweaks is cut into such parts before any edit.

Subagents run in the foreground (`run_in_background: false`), independent ones in parallel as several Agent calls in one message, as many as the ready work allows: the models run on Anthropic's servers and parallel parts cost no more tokens than the same parts in a row, so only the PC's own work limits them, and only a timed measurement (a benchmark, a duel, a frame time), which runs alone, or a cap the project's `TODO.md` head names holds the others back. The main session never ends its turn while one is working, since one left running when the turn ends looks stopped to the owner. A subagent's brief says the same for its own commands (`shell.md`).

A brief carries what the subagent cannot see: the decided design with file and line evidence, what it must not touch, and the rhythm of `verify.md`: its own tests while working, and at the end the linter and type check on its changed files with the tests of the area it touched, then the merge below. After the last part is merged the main session hands the full check to a `haiku` subagent and judges its report; it reads no file or log a report already sums up. A subagent on a decided part (a `sonnet` or `haiku` one, or an `opus` one doing work whose design the brief fixes) runs at the Agent tool's `effort: "medium"`; a hunt or a design keeps the default.

Two subagents never build or test in the same working tree at once: independent work on one repository runs in parallel only in separate worktrees (`isolation: "worktree"`), otherwise one after another. A worktree starts from the local `HEAD`'s last commit (`worktree.baseRef` is `head` in `.claude/settings.json`), without uncommitted work or `node_modules`: Node finds the main tree's up the folders, so a Node project's tools run there by `npx` and `node`, never `pnpm`, which installs first; a package of the repository imported by name resolves to the main tree's copy too, so a change to one is checked there after the merge. Its brief has the agent `cd .claude/worktrees/<name>` first and run every command from there (never a path through `.claude/worktrees/` from the main tree, whatever its tool's description says), check with `git log -n 1` that it holds that commit, and commit on its branch. On Windows, Claude Code compares the session's folder with git's case-sensitively (a known Claude Code bug, anthropics/claude-code#91618): when the session's folder starts with a lowercase drive letter (as VS Code opens it) and git reports it uppercase, `isolation: "worktree"` is refused with "git resolves its working tree to ... (a core.worktree redirect ...)" and leaves a locked worktree behind; no `cd` outlives its call, so the session cannot fix it. Such a session makes the worktree itself: `git worktree add .tmp/wt/<name> -b wt-<name>` (under `.tmp/`, which the project's test runner excludes, like its linter). Its subagent runs every command through `node .tmp/in.js <name> <program> [args...]`, a script running it with cwd `.tmp/wt/<name>` (`spawnSync` with `cwd`, `shell: true` on Windows and `windowsHide`; a `.ps1` runs through `powershell -NoProfile -ExecutionPolicy Bypass -File` and a `.js` through `node`, never handed to the shell, which opens a script in its associated app (Notepad) instead of running it; written with `import`, never `require`, which fails in a `"type": "module"` package; a session missing it writes it again), uses absolute paths under `.tmp/wt/<name>/` for Read, Edit and Write, and commits through the runner with `git commit -F .tmp/msg.txt` (the message in the worktree's own `.tmp/`). After a refusal, remove the leftover with `git worktree unlock <path>` then `git worktree remove --force <path>`, and delete its `worktree-agent-*` branch. A follow-up to a finished subagent is a new foreground Agent call carrying the context it needs; SendMessage resumes it in the background, where the main session cannot wait for it.

Each subagent merges its own part, so dozens can run at once while the main session merges and tests nothing:
1. With its checks passing and its work committed on its branch, it merges in what landed meanwhile: `git merge <base>` in its worktree (`<base>` the branch the main tree has checked out, named in the brief). `TODO*.md` merge item by item through the `todo` driver (`.claude/scripts/todo_merge.js`; where `git config merge.todo.driver` prints nothing, `node .claude/scripts/todo_merge.js --install` first); any other conflict it resolves keeping both sides' intent. If the merge brought changes, it reruns the linter, type check and its area's tests.
2. From the main tree (`cd` back by a relative path, or for a `.tmp/wt/` worktree without the runner) it runs `git merge --ff-only <its branch>`. When that fails because another part landed first, it repeats from step 1; a git lock error is retried.
3. It removes its worktree (`git worktree remove <path>`), deletes its branch (`git branch -d <branch>`), and reports in a few lines: merged or not, and what is left.

A conflict whose resolution needs a decision (two parts changing one behaviour differently) is never guessed: the part stops unmerged, its report naming the branch and the conflict, and the main session decides. While parts run, the main tree holds no uncommitted change to a tracked file, which would block the fast-forward. A part whose work others build on (a shared type, a registry) is merged before they start.
