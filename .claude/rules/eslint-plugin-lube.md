- The package is ESM only like the others; `engines` follows `@stylistic/eslint-plugin`, and a CommonJS `eslint.config.cjs` reaches it through `require(esm)`. `src/index.js` reads the version from `../package.json`.
- Never slice the whole source per node (quadratic); go through `src/utils/source_text.js`. Its edits are what let the nesting rules (`ascii-order`, `pretty-jsdoc-casting`, `pretty-sequence`) verify at `Program:exit` in reverse order and fix every level in one pass.
- Unit tests miss corruption: check a rule fix for an unchanged AST and unmoved comments on real code (files in node_modules, plus the sveltejs/svelte sources for JSDoc casts and comment-led lines), and check that the recommended and strict configs converge there, on CRLF copies too (no bare LF in the output). `lube/indent` conflicts and fixes dropped for overlapping another rule's fix only show up this way. A `@stylistic` fix that breaks code gets a wrapper in `src/index.js`, not a disabled rule.
- `svelte-naming-convention` is run on the sveltejs/svelte repository (JS with JSDoc checked by tsc, `fixSameNames: true`). Check a change there: clone it, camelCase its snake_case locals and their `@param` names by scope, run the fix and compare the AST and the comments with the original.
- It renames every fixable name of a file in one fix, with its declarations, usages, writes, `export { }` specifiers and `export default`: ESLint drops overlapping fixes per pass, so per-name fixes ran the strict config past its 10 passes, and a split rename can leave a usage resolving to another variable or an exported name undeclared (espree rejects it). Module-level names make that one fix span the file, so splitting it by overlapping spans gains nothing. Two names that would become the same snake_case name wait for a later pass, and a name with a declaration or usage the rule never renames (a merged TS namespace, an `eslint-disable`d line) gets no fix at all.
- The strict config must settle in one `eslint --fix` run (10 passes): measure passes on the corpus when a fix's range grows; a fix spanning much code blocks every other rule's fix inside it for that pass, and ESLint drops a fix that merely touches the previous one. `src/utils/trim_fixes.js` cuts every lube and `@stylistic` fix to the text it changes; widening a lube fix or starting it earlier so it wins the sort (a block's start, a shared outer fix on an inner report) raised the corpus total every time. Judge by the total and histogram over the whole corpus, not one file. `esquery/parser.js` from node_modules takes 9, the most.
- Lube rules cooperate only through choices their own fix already makes (the order of what it moves, line breaks): such a choice follows the settings of the other lube rules on for the file (`src/utils/rule_options.js`, recorded by `src/index.js`), as `closures-last` takes `ascii-order`'s order. A fix never also corrects another rule's problem (owner's rule: an editor quick fix applies one rule alone), so overlapping file-wide lube fixes still take a pass each.
- `src/utils/indent_model.js` computes the expected indent for `lube/indent` and for the rules that break lines, so they never cycle: a rule takes its base from `source.get_token_indent(position, indent)` and sets indent only on line breaks it inserts. With `lube/indent` on it returns the model's indent of the token (a list's opener, a ternary's first token); with it off, the physical indent of the token's line (the line a comment or literal spanning it starts on) shifted by the model's offset of the token from that line. Measure every change to the model on the whole corpus before keeping it. A token in mid-line whose base is on an earlier line takes the indent of its line's first token (a JSX text and a statement's body `{` excepted, which stay on the statement's first line), so a bracket opened after a closer (`} of f(`, `); i < bar(`) indents from its own line; a line led by a comment followed by code is indented as that code; JSX indents alike under CR, LF and CRLF; in a `.svelte` `<script>` the first statement keeps its indent and the rest align to it.
- Without semicolons a `(` after a type comment can be the arguments of a call: read the node at that parenthesis before treating it as a casting, and never move white space out of the parentheses a fix removes, or the fix fights `pretty-sequence` forever. For the same reason `pretty-parens` skips a parenthesis right after a `@type` block comment: `pretty-jsdoc-casting` strips the white space inside a cast's parentheses, so its own-line closer would fight it.
- `maxLength` of `pretty-sequence` and `pretty-imports` counts the columns a line takes, so `src/utils/text_width.js` gives a Korean, Chinese or Japanese character the width 2. Counting UTF-16 units instead let a Korean line stay on one line at twice the width of a Latin one the rule had already broken. The message names the width it measured, never "fit in `maxLength`", because the number covers the items alone, without the code around them.
