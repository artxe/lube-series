# material

1. The project's `CLAUDE.md` names its knowledge folders and its ledger of received material. Register the piece there (title, date received, fingerprint: title, first three headings … last). The same fingerprint as a listed one is a re-receipt: re-check only what the last pass skipped; a changed one is an update: compare again.
2. Screen the source: material that lives on selling keeps only claims checkable against primary sources (official documents, statutes, non-seller data); its numbers, testimonials and tool picks are dropped, with the reason.
3. Sort each claim by home: this project's knowledge, a linked project's (`CLAUDE.local.md`), or none (dropped). A linked project's part is never written there: the report gives its distilled gist for the owner to paste into that project's session.
4. Grep each claim against the knowledge folders and the project's own results: known (skip), new, conflicting, or forbidden by the project's rules (one line with the reason, no method).
5. New: only the gist and numbers, with source and source grade, into the matching file; no raw text, no dated timeline or history.
6. Conflicting: check the primary source that day; the project's own measured results win, otherwise the stronger-graded, newer value.
7. Update the folder's `README.md` index (one line per file: what it answers). What changes the work becomes a `TODO.md` item.
8. Report to the owner: what is new and where it went, what conflicted and which value won, what was dropped and why, what was handed to a linked project.
