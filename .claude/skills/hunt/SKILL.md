# Hunt

A hunt first lists the levels its cause can sit at, lowest first (the test's setup against what the domain allows, the layer under the feature measured alone, that layer's known limits, the numbers and units, the feature's own logic), each with the cheapest measurement that clears or convicts it, and clears them in that order, beside how published work and established implementations solve the same problem (their documentation through WebSearch and WebFetch, read before the first fix, not after the tenth); a fix is tried only at a level whose lower levels are cleared. A failed fix widens the hunt, never deepens it: the next part measures a level the fix assumed sound or takes another approach from those sources, never a variant of the same fix. A hunt writes down a hypothesis, the measurement that would refute it and the number it predicts, then measures; the code changes only once a measurement shows one quantity wrong at its source and by how much, and the fix states the number it will bring. A change tried without that is a guess, and guesses are not tried. A hunt's ablations are listed first, then built by one `.tmp/` script from text patches (each variant its own module file) and timed in one A/B run of all of them against the base, never edited, built and timed one at a time. A hunt's probe in a test writes its values to a `.tmp/<name>/` file, never as the values of a failing `expect` (each run counts as a failed call); a test known to fail runs through a `.tmp/` script writing its verdict to a file and exiting 0 unless the run itself errors. A goal judged by an aggregate (a win rate, a score, a frame time, a percentage off) is tuned by the quantities that make it, never by the aggregate alone. After two failed fixes at one goal, however they failed, nobody fixes it again until a new measurement explains both failures. The goal's `TODO.md` item counts the parts spent on it (`parts: 3`); a goal still missed after three parts goes to the owner as a decision (`todo.md`: keep it, loosen the bound to what was reached, or drop it), and its work waits for the answer. Before it goes, check the test's own setup against what the domain allows (in physics, a body the test expects to rest that cannot, as a cube floating at density 0.21–0.79 tips; a target value ignoring the walls): a wrong setup is a bug fixed first and counts as no part. And `CLAUDE.md` may settle the question: an exact mode never loosens below what it is for, and a goal the default cannot meet cheaply splits into a simple default and the exact form as an option; then Claude decides, and only the time it costs is the owner's. The item holds the facts measured so far that narrow the cause, the next measurement, and the failed fixes, at most three lines (what changed, the number it predicted, what came), the oldest dropped first, never a history of what each part did.
